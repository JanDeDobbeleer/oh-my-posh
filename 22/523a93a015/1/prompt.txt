## 10. IA problems

1. **The `/docs` landing page is a Configuration doc.** `configuration/introduction.mdx` carries `slug: /`, so the homepage "Get Started →" button drops users into a conceptual "Introduction" about blocks and segments — which is simultaneously the Configuration category's `link` target. A new user's landing page is not the first sidebar entry, and the Introduction is reachable by two different routes that render the same page. This is the single biggest IA defect.
2. **"Getting Started" has no landing page.** It's a bare category with no `link`, so clicking it just expands. Same for "🌟 Segments", "🧰 CLI"/"☁️ Cloud"/etc. (8 subcategories), "🤝 Contributing", and "🛠️ Advanced". Only Configuration has a landing doc. 3. **Segments are three levels deep and only findable by category guess.** `Segments → CLI → Talosctl` requires knowing that Talosctl is "CLI" and not "Cloud" (it's a Kubernetes/Talos tool; `kubectl` and `helm` and `argocd` are also under CLI, not Cloud). 4. **"🩺 Health" is a mis-scoped bucket.** It holds `nightscout`, `strava`, `withings` (health) alongside `orthodoxcal` and `ramadan` (religious calendars). Those two belong nowhere in the current taxonomy.
5. **Orphaned doc: `docs/auth.mdx`** (id `auth`, "Segment Authentication") is not in the sidebar at all. 6. **Flat top-level docs with no grouping.** `dsc`, `themes`, `share`, `faq`, `migrating`, `contributors` sit loose at root, and `Advanced` (a category with exactly one child, `mcp-server`) is wedged *between* `share` and `faq`. `dsc` and `mcp-server` are both advanced/automation topics but live at different depths. `themes` and `share` are both theme-related but aren't grouped. Two caveats flagged inline: **ghostty.org's homepage is fully client-rendered and its `&lt;main&gt;` stayed empty in a headless browser** (only shell tokens recoverable), and **fig.io is dead** (Fig sunset 2024-09-01, redirected into Amazon Q Developer CLI — remove it from any competitive set).

## 1. starship.rs — the direct competitor

**Above the fold** (https://starship.rs/)
- Hero is the **stock VitePress `layout: home`**: centered `logo.svg`, tagline *"The minimal, blazing-fast, and infinitely customizable prompt for any shell!"*, single action button **"Get Started →"** → `/guide/`.
- **No hero screenshot, no terminal demo, no animation.** For a product whose entire value is visual, this is the single biggest miss.
- Three VitePress feature cards: *Compatibility First* / *Rust-Powered* / *Customizable*.
- Below fold: **Prerequisites** (Nerd Font) then **Quick Install** — install commands and per-shell init snippets for 11 shells inlined directly on the homepage. Effectively the homepage *is* the getting-started page.

**Navigation**: `Configuration` · `Advanced Configuration` · `FAQ` · `Presets` · language switcher (13 locales) · GitHub · appearance toggle. Docs are **landing-page-first for install, sidebar-first thereafter**. Search: Algolia DocSearch in the header (`⌘K`), confirmed in markup.

**Visual language** (extracted from `/assets/style.DFqZBrzq.css`)
- Brand: light `--vp-c-brand-1: #dd0b78`, `-2: #f31186`, `-3: #9b0854`; dark `#ff33b8` / `#ff14ad` / `#ff70cd`. Magenta/pink on otherwise stock VitePress neutrals (`--vp-c-bg: #ffffff` / dark `#1b1b1f`, `--vp-c-bg-alt: #161618`).
- Type: `Inter` for body; **mono stack is prefixed with `"Nerd Font"`** — a nice touch, glyphs in code blocks render correctly.
- Syntax theme in the raw HTML is GitHub-dark-ish: `#9ecbff`, `#b392f0`, `#79b8ff`, `#f97583`, `#6a737d`.
- Dark/light toggle, system default. No gradients, no glass, no grain, no motion. VitePress default radii.

**Doc tech**: VitePress (`#VPContent`, `--vp-*` tokens, `/vp-icons.css`).

**Reference surface**: https://starship.rs/config/ is **one enormous single page** holding ~100 modules. Each module = H2 + Options table (Option/Default/Description) + Variables table + TOML example. Navigation is the right-hand "On this page" TOC + in-page anchors. At this length the right TOC is unusable and browser-find becomes the real interface.

**Preset gallery**: https://starship.rs/presets/ — screenshot cards, each image links to a per-preset page. Copy literally says *"To get details on how to use a preset, simply click on the image."* No filtering, no tags, no live preview, no one-click apply.

**Steal**: Nerd Font in the mono stack; presets-as-images-first; 13-locale i18n.
**Dated**: logo-only hero for a visual product; monolithic config page; unfiltered preset list; zero motion; visibly "default VitePress with a brand color swapped".

## 2. zed.dev

**Above the fold**: announcement bar (*"Early Access: DeltaDB, a new kind of version control"*), headline **"Your last next editor"**, subhead *"Zed is a minimal code editor crafted for speed and collaboration with humans and AI."*, CTAs **"Download now"** (primary) + **"Clone source"** (secondary, GitHub), microcopy *"Available for macOS, Linux, and Windows"*.

**Hero visual**: not a screenshot — a **simulated live product surface**. A recreated Zed chrome with a search field, a scrolling "recent activity" feed of branch names + diff stats + relative timestamps across three repos (`zed`, `cloud`, `zed.dev`), an agent transcript, and a code pane with **real inline diagnostics rendered as text** (`'couldHaveBeenAnEmail' is declared but its value is never read.`). It is DOM, not an image — selectable, crisp at any DPI, and it doubles as a "the project is alive" signal.

**Nav**: `Product` · `Resources` · `Extensions` · `Docs` · `Business` · `Pricing` · `Sign up` · `Download`.

**Below fold**: Fast / Agentic / Collaborative triad → testimonial wall (José Valim, Dan Abramov, Mike Bostock) → "Zed Just Works" video cards → feature card grid → extensions grid → founders' letter → blog.

**Visual language**: Tailwind + Next.js. Brand blue `#084ccf` / `#4482f8`; neutrals `#1b1e23`, `#dae4f8`, `#c6cad0`. **Typography is the differentiator**: self-hosted `IBM Plex Sans`, `IBM Plex Serif` (variable + italic), **`iA Writer Quattro S`** (the duospace face — very unusual on a dev site, gives editorial warmth) and **`Lilex`** for mono. Four families, deliberately.

**Docs**: https://zed.dev/docs/ is **mdBook output (elasticlunr search index) re-skinned inside the Next.js shell**. `S` keyboard shortcut for "Search docs…", light/dark toggle in the docs header. Settings reference is deliberately *not* a giant table — docs push you to the in-app Settings Editor ("search for any setting and change it directly", e.g. `buffer_font_family`). **Agent affordance**: `/docs/llms.txt` index plus Markdown versions of every docs page, advertised in-page.

**Steal**: DOM-rendered product hero; the llms.txt + `.md`-per-page pattern; four-family type system as brand.
**Dated**: nothing much; page weight is enormous (2.7 MB HTML).

**Below fold**: "Four tools, one toolkit" → benchmarks → "Who uses Bun?" (Claude Code, Railway, Midjourney) → comparison tables → API overview → framework interop → per-subcommand benchmark sections (`$ bun install`, `$ bun test`) → API carousel → testimonial carousel.

**Steal**: install box *as* the hero with platform toggle and version-in-button; generated reference as its own searchable app; benchmarks with hard numbers above the fold.

## 4. biomejs.dev

**Above the fold**: **"One toolchain for your web project"** / *"Format, lint, and more in a fraction of a second."* CTAs **"Get started"** + **"View on GitHub"**. Hero visual = logo lockup only — same weakness as Starship.

**Nav**: `Docs` · `Enterprise` · `Playground` · `Blog` + theme/lang selectors + version switcher (v1.x / v2.x / next).

**Below fold**: Formatter with before/after code → Linter with a **real rendered diagnostic** (the terminal-style error block with source excerpt, caret, and suggestion — the strongest section) → unified `check` → 6 feature callouts → org logo grid (Astro, AWS, Cloudflare, Discord, Google, Microsoft, Vercel) → contributor avatars → sponsors.

**Doc tech**: **Astro v7.1.0 + Starlight v0.41.3** (confirmed via dual `&lt;meta name="generator"&gt;`), **Pagefind** for search (fully static, no Algolia dependency).

**Visual language**: Starlight tokens overridden — `--sl-color-accent: #3d50f5` (light) / `#3369ff` (dark), `-high: #0f1c8a` / `#b3c7ff`, `-low: #cfd4fc` / `#131e4f`, greys `#23262f`/`#24272f`. Radii are conservative: `.25rem`, `.3rem`, `.5rem`, `8px`, `12px`. Syntax theme is **Night Owl** (`#403f53`, `#d6deeb`, `#c792ea`, `#7fdbca`, `#82aaff`, `#ecc48d`). Diagnostic colors `#b23834`/`#e2817f`/`#d9f5dd`/`#caece6`.

**Reference surface (511 rules)** — https://biomejs.dev/linter/javascript/rules/
- **Split by language first** (`/linter/javascript/rules`, `/css/rules`, `/json/rules`, `/graphql/rules`, `/html/rules`), then by **9 semantic groups** (a11y, complexity, correctness, nursery, performance, security, style, suspicious).
- Each group = a **table**: rule name (link) · one-line description · **badge column** (✓ recommended, 🔧 safe fix, ⚠️ unsafe fix, 🔮 next release), with a legend.
- A trailing **"Recommended rules"** section re-cuts the same set by severity — a *second view of the same data* for a different intent.
- **No client-side filtering.** Discovery is Pagefind + browser find.

**Steal**: two-axis split (language × group) before a flat list; badge column as scannable metadata; second re-cut view of the same catalog; Pagefind (zero-infra static search); the rendered-diagnostic hero block.
**Dated**: logo-only hero; a static table is straining at 511 rows.

## 8. ghostty.org

⚠️ **Caveat**: the homepage is Next.js App Router with a fully client-rendered `&lt;main class="home-content-module__…homePage"&gt;` that **stayed empty** in my headless browser (no canvas, no video, no wasm in the resource log — only two font requests). WebFetch also returned title-only. So no verified hero copy.

What is verifiable:
- Body background `rgb(15, 15, 17)` = **`#0f0f11`, dark-only**; body font **`Pretendard Std Variable`** (self-hosted variable woff2) — a distinctive, non-Inter choice. Next.js + CSS Modules.
- Positioning line used across the site: *"Ghostty is a fast, feature-rich, and cross-platform terminal emulator that uses platform-native UI and GPU acceleration."*
- Nav: `Docs` · `Discord` · `GitHub` · `Download`.
- **Docs sidebar** (https://ghostty.org/docs): About Ghostty · Install · Configuration · Linux · Features · Terminal API (VT) · Help · Financial Support. Landing uses feature cards into each section.
- **Download page** is per-OS *sections* (macOS / Linux), version prominent ("Version 1.3.1"), links to release notes and to package-manager/build-from-source docs — **no inline copy-command**, which is weaker than Bun/Atuin.
- **Config reference** (https://ghostty.org/docs/config/reference): a **single page with hundreds of options**, ordered "roughly by how common they are… grouped with related options". Each entry: name heading, description, valid values, platform notes, **"Available since: 1.2.0"**, cross-references. The page explicitly tells you to *"utilize your browser's search functionality"* and admits *"In the future, we'll have a more user-friendly way to view and organize these options."*

**Avoid**: a JS-only homepage that renders nothing without hydration (bad for crawlers, agents, and my own tooling); a config reference whose own maintainers call it unfit.

# Synthesis

## A. The 3–4 dominant idioms in 2026

**1. The hero *is* the install command, and the version number lives in the button.**
Bun (`Install Bun v1.3.14` + Linux/macOS↔Windows toggle), Atuin (copy-box + `$ get-started`), Astro (`npm create astro@latest`, "Copied!"), Tauri (9-way package-manager tabs), Starship (install block inlined on the homepage). Nobody makes you click through to a getting-started page to see the command. Corollary: **Ghostty's download page, which offers no copy-command, is the outlier and it reads as friction.**

**2. Product surfaces are re-rendered in the DOM, not screenshotted.**
Zed's activity feed + code pane with real inline diagnostics; Atuin's `demo-term`; Biome's rendered diagnostic block; Warp's interactive configurator; Bun's syntax-highlighted API carousel. Benefits: crisp at every DPI, selectable/copyable, themeable, dark/light-reactive, diffable in git, and localizable. **PNG screenshots now read as dated** — which is precisely what Starship's presets page and Oh My Posh's theme gallery both are.

**3. Dark-first, but with *zoned* dark rather than one flat black.**
Ghostty `#0f0f11` dark-only; ray.so `#0d0d0d`; Warp stacks `#0b0b0b`/`#111111`/`#1f1f1f` and then adds **tinted section washes** (`#1e142a` purple, `#141e30` blue, `#1a2a1a` green, `#201a14` amber) to color-code content zones; Atuin `#0f1722` with a green/warm-cream dual accent. The 2026 refinement over 2023 is calibrated multi-step neutral ramps plus one saturated accent — **not** gradient-mesh, not glassmorphism, not noise/grain (I found essentially none of those in this cohort). Motion is minimal and confined to hero and section transitions.

**4. Typography is now the brand.**
Zed runs four self-hosted families (IBM Plex Sans, IBM Plex Serif, iA Writer Quattro S, Lilex). Ghostty picked Pretendard Variable. Atuin picked DM Sans + Space Mono. Bun deliberately uses `system-ui`. The tools that read as "default template" are exactly the ones on stock Inter over a stock generator theme — **Starship and Oh My Posh both sit in that bucket.** For a prompt engine specifically: **Starship prepends `"Nerd Font"` to its mono stack** so glyphs render in code blocks; that is a one-line, high-leverage steal.

**Emerging fifth idiom — the agent affordance.** Bun (`/docs/llms.txt`), Zed (`/docs/llms.txt` **plus a `.md` version of every page**, advertised in-page). This is becoming table stakes and is cheap on any generator.

## B. Navigating a large reference surface — what actually works

Observed strategies, ranked by how well they hold up:

| Strategy | Who | Verdict |
|---|---|---|
| **Split the reference by axis before listing** (language × category) | Biome: 5 language pages × 9 groups | **Best.** No single page exceeds ~80 rows. |
| **Facet dropdown over a card grid** | Tauri plugins (platform filter + `Ctrl+K`) | **Best-in-cohort interaction.** Only site that filters in the browser. |
| **Group by provenance/domain, table per group** | Ruff (~50 linter groups), Biome | Scales to ~900 rows but is scroll-and-find, not filter. |
| **Generated reference as its own searchable app** | Bun `/reference` (from TS types, own search field) | **Strong** — separates hand-written prose from machine truth, and never drifts. |
| **Second re-cut of the same catalog** | Biome "Recommended rules" by severity; Ruff "Default rules" | Cheap, high value — serves a different intent from the same data. |
| **Capability matrix table** | Tauri plugin × 5 platforms | Excellent for cross-cutting support questions. |
| Single giant page + right-hand TOC | Starship `/config/` (~100 modules) | **Breaks.** TOC is unusable at this length. |
| Single giant page + "use browser find" | Ghostty config reference | **Breaks, and maintainers say so in the page.** |
| Static table, discovery offloaded to CLI/TUI | mise registry (1000+ tools) | Defensible for a CLI, **fails as a web discovery surface.** |

**The pattern that keeps recurring in the ones that work**: metadata rendered as a **badge column** rather than prose — Biome (✓ recommended / 🔧 safe fix / ⚠️ unsafe fix / 🔮 next release, with a legend), Ruff (stable/preview/deprecated/removed + 🛠️ auto-fix), Ghostty (**"Available since: 1.2.0"** and platform-scope notes per option). Badges are scannable, filterable if you later add JS, and answer "can I use this yet?" without opening the page.

**Ordering**: Ghostty orders options **by frequency of use and semantic grouping, not alphabetically**. Oh My Posh's segment sidebar is alphabetical-within-category; frequency ordering (or a "most used" cluster) would surface `git`, `path`, `python`, `node` above `argocd`.

## C. Theme gallery / showcase patterns

**The reference implementation is ray.so/themes** (Raycast's Theme Explorer, open source at `raycast/ray-so`). Verified in-browser:
- **Live-rendered preview, not a screenshot** — the actual app chrome ("Search for apps and commands…", list rows, primary text) rendered in the theme's own colors, in DOM.
- **Dark / Light segmented toggle** at gallery level, each linking to a representative theme (`/chris/almost-cyan`, `/luxonauta/alucard`).
- **URL is `/{author}/{theme-slug}`** — every theme is individually addressable and shareable; theme state is encoded in the URL.
- **One-click "Add to Raycast"** deep-link — zero copy-paste between browse and apply. This is the single biggest conversion lever and nothing in the Oh My Posh cohort has it.
- Authoring loop closed: Theme Studio → right-click → *Copy as URL* (produces a gallery link) or *Copy as JSON*. **The gallery is the sharing format.**
- Dark `#0d0d0d`, Inter, Radix-style grey scales (`gray-2`…`gray-12`, `gray-a4`…`gray-a11`), pill/`rounded-md` radii.

Supporting patterns:
- **Card anatomy** (Astro themes, Vercel templates): thumbnail · title · 1–2 line description · **author avatar + name** · status pill. Authorship is what makes a community gallery feel like a community.
- **Faceted sidebar with per-facet counts and a global "Clear"**, URL-driven so filter state is shareable/bookmarkable — Vercel `/templates` is the model (Use Case / Framework / CSS / Database / Auth / CMS, each with a selected-count indicator).
- **Tiering**: Tauri's official-cards-vs-community-links, Astro's featured/sponsor row. Useful, but see anti-patterns.
- **Screenshot cards linking to per-item pages** — Starship presets. Minimum viable; what Oh My Posh has today, minus even the per-item page.

**Concrete implication for an Oh My Posh theme gallery**: render prompts as HTML/CSS from the theme JSON (segments, colors, powerline separators, Nerd Font glyphs) instead of committing 150 PNGs; give each theme `/themes/{name}`; facet by *needs Nerd Font · has powerline · segment count · light/dark · segments used*; add a one-click apply (copy `oh-my-posh init pwsh --config &lt;url&gt;` or a deep link); and let the same renderer power previews on segment reference pages.

## D. Anti-patterns to avoid

1. **Logo-only hero for a visual product.** Starship and Biome both lead with a logo. If the product's value is what appears on screen, the hero must show it. Atuin, Zed, and Bun all do.
2. **Screenshot galleries.** 150 PNGs are stale on merge, unfilterable, un-themeable, invisible to search, and heavy. Render from source data.
3. **The monolithic reference page.** Starship's `/config/` and Ghostty's config reference are the two clearest failures in this study — and Ghostty's own docs concede it.
4. **Catalogs with no in-browser filter.** Ruff (900 rules), Biome (511), mise (1000 tools), Astro themes (hundreds) — all rely on browser find or an external search. Tauri's platform dropdown is the lone counterexample and it's trivially cheap.
5. **A JS-only homepage.** ghostty.org served me an empty `&lt;main&gt;` with a browser attached. Whatever agents, crawlers, and link previews see, that's what they see too. Anything above the fold should be in the HTML.
6. **Enterprise mega-menu drift.** Warp's `Solutions › Industry › Insurance` taxonomy on what people still install as a terminal. For an OSS tool, a 4–6 item nav (Atuin: History · AI · Blog · Docs; Ghostty: Docs · Discord · GitHub · Download) is correct.
7. **Sponsored-first gallery ordering.** Astro's themes page is 12+ "Paid" cards deep before community work appears. Corrosive to an OSS community gallery.
8. **Version-number headlines.** "Tauri 2.0" tells a first-time visitor nothing. Put the version in the install button (Bun) instead.
9. **Un-themed default generators.** Stock VitePress with one swapped brand color (Starship), stock Material for MkDocs (uv, ruff), stock Docusaurus (Oh My Posh). Instantly legible as "we didn't design this." The cheapest fix with the largest return is **type + a calibrated neutral ramp**, not illustration.
10. **Emoji as sidebar taxonomy.** Oh My Posh's `💡 Getting Started` / `✨ Prompt` doesn't survive translation, search indexing, or scanning at density.
